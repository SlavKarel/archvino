# Internationalization (i18n)

This document describes the internationalization system used in archvino.

## Overview

The project supports two locales: Russian (`ru`) and English (`en`). The i18n system is implemented in `src/lib/i18n.ts` and used throughout the codebase for routing, content storage, and UI strings.

---

## Locale System

### Constants and Types

```typescript
// src/lib/i18n.ts
export const LOCALES = ['ru', 'en'] as const;

export type Locale = (typeof LOCALES)[number];  // 'ru' | 'en'

export const DEFAULT_LOCALE: Locale = 'ru';
```

**Key definitions:**

- `LOCALES` — readonly tuple of supported locales
- `Locale` — TypeScript union type (`'ru' | 'en'`)
- `DEFAULT_LOCALE` — fallback locale when none is specified

---

## LocalizedString Type

Content that requires translation uses the `LocalizedString` type:

```typescript
export type LocalizedString = Record<Locale, string>;
```

### YAML Content Example

In YAML files, bilingual content is stored as nested objects:

```yaml
title:
  ru: Студия-лофт
  en: Studio Loft

location:
  ru: Санкт-Петербург
  en: Saint Petersburg
```

See `src/content/projects/studio-loft.yaml` for a complete example.

## Helper Functions

All i18n utilities are exported from `src/lib/i18n.ts`.

### isLocale() — Type Guard

Validates whether a string is a valid locale.

```typescript
import { isLocale, type Locale } from './i18n';

function handleLocale(value: string): Locale | undefined {
  if (isLocale(value)) {
    return value;  // TypeScript knows value is Locale here
  }
  return undefined;
}
```

### getLocalizedValue() — Get Translated Value

Retrieves the value for a specific locale from a `LocalizedString`.

```typescript
import { getLocalizedValue, type Locale } from './i18n';

const title: LocalizedString = {
  ru: 'Студия-лофт',
  en: 'Studio Loft'
};

const locale: Locale = 'en';
const result = getLocalizedValue(title, locale);  // 'Studio Loft'
```

### getAlternateLocale() — Get Opposite Locale

Returns the other supported locale.

```typescript
import { getAlternateLocale } from './i18n';

getAlternateLocale('ru');  // 'en'
getAlternateLocale('en');  // 'ru'
```

### buildLocalePath() — Build Localized URLs

Creates a locale-prefixed path.

```typescript
import { buildLocalePath, type Locale } from './i18n';

const locale: Locale = 'ru';

buildLocalePath(locale, '/');           // '/ru/'
buildLocalePath(locale, '/projects');   // '/ru/projects'
buildLocalePath(locale, '/about');      // '/ru/about'
```

## URL Routing

Routes are structured with locale as the first path segment:

```
/ru/           → Russian home page
/en/           → English home page
/ru/projects/  → Russian projects page
/en/projects/  → English projects page
```

### Dynamic Route Parameter

Astro pages use `[locale]` as a dynamic parameter:

```typescript
// src/pages/[locale]/index.astro
export function getStaticPaths() {
  return LOCALES.map((locale) => ({ params: { locale } }));
}

const { locale: localeParam } = Astro.params;

if (!localeParam || !isLocale(localeParam)) {
  return Astro.redirect('/ru/');
}

const locale: Locale = localeParam;
```

### Route Helpers

Additional path builders are in `src/lib/routes.ts`:

```typescript
import { buildHomePath, buildPagePath, buildProjectPath } from './lib/routes';

buildHomePath('ru');           // '/ru/'
buildPagePath('ru', 'about');  // '/ru/about'
buildProjectPath('ru', 'villa-moscow');  // '/ru/projects/villa-moscow'
```

## Locale Switcher

The `LocaleSwitcher` component allows users to switch between languages while preserving the current page.

### Component Usage

```astro
---
// src/components/site/Header.astro
import LocaleSwitcher from './LocaleSwitcher.astro';

const { locale, pathname, localeLabels } = Astro.props;
---

<LocaleSwitcher locale={locale} pathname={pathname} labels={localeLabels} />
```

### Component Source

```astro
---
// src/components/site/LocaleSwitcher.astro
import type { Locale } from '../../lib/i18n';
import { LOCALES } from '../../lib/i18n';
import { buildLocaleSwitchPath } from '../../lib/routes';

type Props = {
  locale: Locale;
  pathname: string;
  labels: Record<Locale, string>;
};

const { locale, pathname, labels } = Astro.props;
---

<div class="locale-switcher" aria-label="Locale switcher">
  {
    LOCALES.map((targetLocale) => (
      <a
        href={buildLocaleSwitchPath(pathname, targetLocale)}
        hreflang={targetLocale}
        title={labels[targetLocale]}
        aria-label={`${targetLocale.toUpperCase()} ${labels[targetLocale]}`}
        aria-current={targetLocale === locale ? 'page' : undefined}
      >
        {targetLocale.toUpperCase()}
      </a>
    ))
  }
</div>
```

### Path Switching Logic

The `buildLocaleSwitchPath` function in `src/lib/routes.ts` handles converting current paths:

```typescript
export function buildLocaleSwitchPath(currentPath: string, targetLocale: Locale): string {
  const normalizedPath = currentPath.replace(/\/+$/, '') || '/';

  if (normalizedPath === '/') {
    return buildHomePath(targetLocale);
  }

  const segments = normalizedPath.split('/').filter(Boolean);

  // No locale prefix (shouldn't happen with current routing)
  if (!isLocale(segments[0])) {
    return buildLocalePath(targetLocale, normalizedPath);
  }

  // Already has locale prefix — replace it
  const nextPath = segments.slice(1).join('/') || '/';
  return buildLocalePath(targetLocale, nextPath);
}
```

## Usage Patterns

### In Pages

```typescript
// src/pages/[locale]/index.astro
export async function getStaticPaths() {
  return LOCALES.map((locale) => ({ params: { locale } }));
}

const { locale: localeParam } = Astro.params;
if (!localeParam || !isLocale(localeParam)) {
  return Astro.redirect('/ru/');
}
const locale: Locale = localeParam;

const content = await getHomePageContent(locale);
const title = getLocalizedValue(content.title, locale);
```

### In Layouts

```astro
---
// src/layouts/BaseLayout.astro
import type { Locale } from '../lib/i18n';

const { locale, title, description, image } = Astro.props;
---
<html lang={locale}>
  <head>
    <title>{title}</title>
  </head>
  <body>
    <slot />
  </body>
</html>
```

### Schema for Localized Content

Content collections use Zod schemas with `LocalizedString`:

```typescript
// src/content.config.ts
const localizedStringSchema = z.object({
  ru: z.string(),
  en: z.string(),
});

const projectSchema = z.object({
  title: localizedStringSchema,
  summary: localizedStringSchema,
  location: localizedStringSchema,
  status: localizedStringSchema,
  // ...
});
```
